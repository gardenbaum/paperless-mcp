# Paperless-ngx reading guide (relevance triage for paperless-mcp)

Read this before any work on the Paperless adapter, fakes or tools, then open the specific
source. Do not answer from memory: Paperless 3.x changed search (Tantivy), raised the API version
to 10 and added document versions and AI features. Refresh with `just docs-sync-paperless`
(version pinned as `PAPERLESS_VERSION` in the `justfile`).

Vendored in `docs/vendor/paperless/` (marker in `UPSTREAM`: commit, tag and the digest of the
image the schema was generated from):

| File | What it is |
|---|---|
| `openapi.json` | OpenAPI 3.0.3 schema generated by drf-spectacular from the pinned image. **Authoritative for request and response shapes**; the schema-guard tests validate the adapter against it. Pretty-printed, about 700 KB: search it (`jq`, `grep`), never read it whole. |
| `api.md` | REST API narrative: auth, search parameters, custom field queries, uploads, versions, permissions, bulk edit, API version changelog. |
| `usage.md` | User-facing behaviour: permissions, workflows, custom fields, PDF actions, trash, AI features, **search syntax** (section "Searching"). |
| `advanced_usage.md` | Matching algorithms, AI setup (LLM index, chat), filename templates. |
| `migration-v3.md` | What changed in v3 (search index Whoosh to Tantivy, `notes.note:` and `custom_fields.value:` syntax, task history). |

## Read first

- `api.md` section "API Versioning" and its changelog. We are on **version 10**: every request
  sends `Accept: application/json; version=10`. Changes in v10 that matter: document-editing
  operations (`merge`, `rotate`, `edit_pdf`, ...) live on their own endpoints (the
  `bulk_edit` forms are deprecated), bulk edit of objects takes `all` and `filters`, the
  `title_content` filter is deprecated in favour of `text` and `title_search`, the list parameter
  `all` is deprecated, tasks were redesigned (paginated, `task_type`, `trigger_source`,
  `summary`, `status_counts`, `active`, `run`), saved views lost `show_on_dashboard` and
  `show_in_sidebar`, and `created` is a date (v9).
- `api.md` section "Authorization": `Authorization: Token <token>` for API tokens (also basic,
  session, remote user, headless OIDC). The credential is opaque to the code; the header comes from it.
- `api.md` section "Searching for documents" and `usage.md` section "Searching": on
  `/api/documents/`, `text` (title and content, substring style), `title_search`, `query` (full
  query language) and `more_like_id`. Results carry `__search_hit__` (`score`, `highlights`, `rank`).
- `usage.md` "Document searches" (combining terms, `field:value`, wildcards, dates) and
  `migration-v3.md` "Search Index": the Tantivy query language. Notes are `notes.note:`, custom
  fields `custom_fields.value:` and `custom_fields.name:`; the old `note:` and `custom_field:`
  prefixes are gone.
- `api.md` "Filtering by custom fields": the `custom_field_query` JSON expression (`[field, operator, value]` triples,
  combinable with `"AND"` and `"OR"`) versus the simpler `custom_fields__*` filters.

## Needed by specific tools

- Bulk edit: `api.md` "Bulk Editing" (`/api/documents/bulk_edit/` for metadata methods,
  `/api/bulk_edit_objects/` for tags and other objects, with `all` and `filters`). The PDF
  operations have separate endpoints in `openapi.json`: `/api/documents/{merge,rotate,edit_pdf,remove_password,reprocess,delete}/`.
- Versions: `api.md` "Document Versions" (`update_version`, `merge_as_versions`,
  `versions/{version_id}`, `?version=` on content, download, preview, thumb and metadata).
- Permissions: `api.md` "Permissions" and "Retrieving full permissions" (`owner`,
  `set_permissions` with `view` and `change` for users and groups; list responses are truncated
  unless `full_perms=true`); `usage.md` "Permissions" for the model.
- Uploads: `api.md` "POSTing documents" (`/api/documents/post_document/`, returns a task id
  string); follow the task with `/api/tasks/` (v10 shape).
- Notes: `/api/documents/{id}/notes/` in `openapi.json`. Trash: `/api/trash/` (list, restore,
  empty); `usage.md` "Document Trash". History: `/api/documents/{id}/history/`.
- Workflows (`usage.md` "Workflows": triggers, filters, actions, placeholders) map to
  `/api/workflows/`, `/api/workflow_triggers/`, `/api/workflow_actions/`. Mail: `usage.md`
  "Incoming Email" and `/api/mail_accounts/`, `/api/mail_rules/`, `/api/processed_mail/`.
- Sharing: `/api/share_links/`, `/api/share_link_bundles/`, `/api/documents/{id}/email/`; `usage.md` "Sharing documents".
- AI: `usage.md` "AI Features" and `advanced_usage.md` "AI features" (opt-in and server-configured;
  document content goes to the configured provider). Endpoints: `/api/documents/chat/`,
  `/api/documents/{id}/ai_suggestions/` and the classifier-based `/api/documents/{id}/suggestions/`.
  Expect them to be disabled or erroring on an instance without AI configured.
- Admin: `/api/users/`, `/api/groups/`, `/api/config/`, `/api/logs/`, `/api/status/`,
  `/api/statistics/`, `/api/remote_version/`, `/api/ui_settings/`.
- Matching and automation (`advanced_usage.md` "Matching") explains why a document lands in a
  tag or correspondent without the API being involved.

## Where to look in `openapi.json`

- Paths: `jq '.paths | keys[]'` lists all 93; each operation has `operationId`, `tags`, `parameters`, `requestBody`, `responses`.
- Shapes: `.components.schemas.<Name>` (208 schemas). Names ending in `Request` are request
  bodies, `Patched...Request` are PATCH bodies, `Paginated...List` are page envelopes.
- Document list filters are the query parameters of `GET /api/documents/` (`added__date__gt`,
  `tags__id__all`, `custom_field_query`, `query`, ...). Check the parameter list before
  assuming a filter exists. Known gap: `more_like_id` and `all` are documented in `api.md` but absent from the generated parameter list.
- Security schemes: `tokenAuth`, `cookieAuth`, basic.
- Note: the schema is generated from code, so some responses of custom actions are loosely
  typed. When the schema is vague, `api.md` and the Paperless source of the same tag decide.

## Skip

- `advanced_usage.md` consume hooks, filename templates and placeholders, parser plugins, MySQL notes, Celery monitoring.
- `usage.md` web UI, mobile upload, keyboard shortcuts, recommended workflow, remote OCR, architecture.
- `migration-v3.md` except "Search Index", "Task History", and the "Secret Key" requirement (relevant to E2E setup).
- `/api/token/`, `/api/profile/`, `/api/oauth/` and other login flows: the server receives a ready credential.
