## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Live probe on 3.4.2 (admin and e2e-reader, plmcp24- fixtures, cleaned up): versions are listed in GET /api/documents/{id}/ (newest first, root last; fields id, added, version_label, checksum, is_root); POST update_version takes multipart document + version_label and answers a JSON string (consume task id); the task's related_document_ids/result_data.document_id is the NEW VERSION id; the file type is sniffed server-side (octet-stream 400 at POST), an image without DPI fails the task not the POST, duplicate content makes a second version with the same checksum; blank version_label becomes null, 65 chars is 400; PATCH versions/{id}/ answers the version (root label can be set); DELETE versions/{id}/ answers 200 {result:OK,current_version_id} (schema says 204), the root is 400 text/html 'Cannot delete the root/original version', unknown or foreign version 404; a deleted version goes to the TRASH (restorable via /api/trash/ restore, brings the version back); merge_as_versions is synchronous 200 {result:OK}, the SOURCE documents vanish for good (404, not in trash, notes and metadata lost), sources that have versions are 400 'Documents with existing versions cannot be merged into another document.', version_label only with one source, duplicate ids 400; a viewer without change grant gets 403 on PATCH/DELETE/update_version and 403 text/html on merge; hidden document 404.

Source read in the 3.4.2 image (documents/views.py, permissions.py) to model permissions in the fake; the live contract run is the oracle: upload_document_version (POST update_version) needs global add_document (DRF) AND change_document plus has_perms_owner_aware(change) on the root (owner, unowned, superuser or a change grant); the form is validated (400) before the document is looked up (404) or the permission checked (403); update_version on a version id resolves to its root. PATCH label: global change_document + owner-aware change; 400 for a 65-char label comes first. DELETE version: global delete_document + owner/unowned/superuser (a change grant is NOT enough), then version 404, root 400 (text/html). merge_as_versions: form first (hidden documents are not 'missing': they are a 403), then for non-superusers global change_document + change grant on all + OWNERSHIP of all (owner None or self) + global delete_document, because the sources stop existing; a change grant alone is 403 (contract test pins it). Deleted version = soft delete into the trash under its own id, restorable via /api/trash restore (verified), so delete_document_version carries confirm per decision-15 though recoverable; merge removes the sources for good (no trash, notes and metadata lost) so merge_documents_as_versions ALSO takes confirm although the task text lists confirm only for delete: stricter, deliberate. Tool surface (versions toolset, opt-in, not in the default profile: default stays 18 of 20): list_document_versions, upload_document_version (content_base64 variant, stdio+PAPERLESS_MCP_UPLOAD_DIRS adds a path variant exactly like upload_document, same size limit, MIME sniff, filename cleaning, allowlist and check_transport), set_document_version_label (blank clears, max 64), delete_document_version (confirm), merge_documents_as_versions (confirm, 1..20 sources, label only with one source). Design points: versions are read through get_document (no new reader port; DocumentVersion gained checksum, SHA-256 of the file, live-verified); writer ports upload_document_version, set_version_label, delete_version, merge_as_versions; services/task_outcome.follow was extracted from UploadService so both uploads share the 'task id always gets out' logic; the newest version is versions[0] (Paperless order, live-verified after upload and delete).

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Adds the opt-in versions toolset (default profile unchanged at 18 of 20; only list_document_versions survives read-only): list_document_versions, upload_document_version (same size cap, MIME sniffing, filename cleaning and stdio-only allowlisted path variant as upload_document, with check_transport now shared in tools/_shared), set_document_version_label, delete_document_version (confirm; the version goes to the trash; the root is refused) and merge_documents_as_versions (confirm, stricter than the task asks because the sources vanish for good; the prompt names notes lost and the file the root then shows). Unchangeable documents are refused before the prompt where the record says so; a merge invalidates the cached taxonomy counts, and a failed read after a merge is reported instead of raised. A new import-linter contract keeps toolset modules independent (decision-1). Live-verified 3.4.2 facts are in the notes (version DELETE answers 200 with current_version_id, merge is synchronous and permanent, per-endpoint permission rules). Gates: just check, just mutation 100 %, CI e2e green; locally the full e2e is green except test_more_like_finds_other_documents on the stale shared index. Deliberate changes: additions-only surface snapshots (checksum on DocumentVersion, the five tools, a stdio snapshot, nullable VersionsMerged.versions), schema-guard form and maxLength checks with three documented WRONG_RESPONSE_SCHEMAS entries, reviewed mutation equivalents. DoD #1 left unchecked: the e2e tests and snapshots were written after the code, and the fake's permission model was corrected after live contract tests failed.
